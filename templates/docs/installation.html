CDN (Recommended)

Add the SDK to any HTML page. Always serves the latest version with no-cache headers.

HTML
<script src="https://lemma.id/sdk/lemma-wallet.js"></script>

No API key. No configuration. No build step. The SDK is self-configuring.

Static Hosting (Versioned)

If you need a specific version pinned for production stability:

HTML
<!-- Pinned version (update manually) --> <script src="https://lemma.id/static/js/lemma-wallet.js?v=2.50.0"></script>

Backend Requirements

Lemma.id is backend-agnostic. Your server needs exactly one endpoint:

Any Language
POST /api/auth/lemma Body: { "ppid": "did:lemma:ppid_abc123..." } Response: - If PPID exists in your database: sign in (create session) - If PPID is new: create account + sign in

No password hashing libraries. No OAuth client libraries. No token management. Your backend receives a PPID and stores it. That's the entire integration.

Register Your Site

Register your domain on the Developer Dashboard to enable lemma issuance. This is required so Lemma.id knows which sites are authorized to receive signed credentials.

Why registration?

Site registration ensures only authorized domains can request lemma issuance. The signing key for your site is unique and KMS-encrypted. No other site can issue credentials that appear to come from yours.

Running Alongside Existing Auth

Lemma.id doesn't replace your existing auth -- it sits alongside it. Add a lemma_ppid column to your users table:

SQL
ALTER TABLE users ADD COLUMN lemma_ppid TEXT UNIQUE;

Users can sign in with Lemma.id, Google, or password. Link accounts by associating a PPID with an existing user record.
