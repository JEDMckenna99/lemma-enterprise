What is Lemma.id?

Lemma.id replaces passwords and OAuth with hardware-backed passkeys and locally-verifiable credentials. Users authenticate once with a passkey on lemma.id, and every site they visit can verify their identity instantly -- no network calls, no tokens, no shared secrets.

For developers

Your integration is: 1 script tag + 1 backend endpoint. The SDK handles passkeys, credential issuance, Ed25519 verification, cross-device sync, and revocation. Your backend just stores a pseudonymous ID.

How It Works

First visit (one-time setup)

  1. User clicks "Sign in with Lemma.id" on your site
  2. Redirects to lemma.id -- user taps passkey (biometric)
  3. Lemma.id issues a signed credential (lemma) for your site
  4. Redirects back -- SDK stores credential in your site's IndexedDB
  5. Your backend receives the user's PPID (site-specific pseudonymous ID)

Every visit after (instant, zero network calls)

  1. SDK reads credential from IndexedDB (~2ms)
  2. Ed25519 signature verification (local WebCrypto, ~1ms)
  3. Check unlock state (in-memory, ~0ms)
  4. Return PPID to your code -- user is authenticated

Total: <5ms. No calls to lemma.id. No calls to your server for auth.

Lock and unlock (SSE real-time push)

  • User locks wallet on any device -- SSE pushes session_invalidated to all sites in <100ms
  • User unlocks on another device -- SSE pushes session_restored to all sites in <100ms
  • No polling. No heartbeats. Persistent EventSource connection.

Security Model

Credentials can't be forgedEd25519 signatures, private key in HSM (AWS KMS)

Cross-site tracking preventedPPIDs are site-specific: HMAC(wallet_secret, site_domain)

What Your Site Never Sees

  • No passwords (none exist)
  • No email addresses (unless you ask for one separately)
  • No OAuth tokens (no token refresh, no expiry management)
  • No wallet secrets (stays on lemma.id, used only for PPID derivation)
  • No passkey material (hardware-bound, never leaves device)

Your site stores one column: lemma_ppid. If your database is breached, the attacker gets pseudonymous IDs that are meaningless without the wallet secret (which you never had).
