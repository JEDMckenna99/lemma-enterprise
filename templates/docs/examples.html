Basic Integration

The minimal complete example. One script tag, one button, one backend endpoint.

HTML + JavaScript
<script src="https://lemma.id/sdk/lemma-wallet.js"></script> <button id="sign-in" style="display:none">Sign in with Lemma.id</button> <div id="user-info" style="display:none"></div> <script> const wallet = new LemmaWallet(); async function init() { const result = await wallet.getAuthenticatedPPID(); if (result.authenticated) { // Tell your backend await fetch('/api/auth/lemma', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ ppid: result.ppid }) }); document.getElementById('user-info').style.display = 'block'; document.getElementById('user-info').textContent = 'Signed in'; } else { document.getElementById('sign-in').style.display = 'block'; } } document.getElementById('sign-in').addEventListener('click', () => { wallet.unlockWithRedirect({ returnUrl: window.location.href }); }); init(); </script>

Running Alongside Google Auth

Add Lemma.id as another sign-in option without touching existing auth.

Database Schema
-- Add to your existing users table ALTER TABLE users ADD COLUMN lemma_ppid TEXT UNIQUE;
Python (Flask)
# Existing Google auth - unchanged @app.route('/api/auth/google', methods=['POST']) def google_auth(): google_id = verify_google_token(request.json['token']) user = User.query.filter_by(google_id=google_id).first() if not user: user = User(google_id=google_id, email=get_google_email(google_id)) db.session.add(user) db.session.commit() session['user_id'] = user.id return jsonify({'success': True}) # NEW: Lemma auth - 10 lines @app.route('/api/auth/lemma', methods=['POST']) def lemma_auth(): ppid = request.json.get('ppid') user = User.query.filter_by(lemma_ppid=ppid).first() if not user: user = User(lemma_ppid=ppid) db.session.add(user) db.session.commit() session['user_id'] = user.id return jsonify({'success': True}) # Link Lemma to existing account @app.route('/api/auth/link-lemma', methods=['POST']) def link_lemma(): if not session.get('user_id'): return jsonify({'error': 'Must be signed in'}), 401 ppid = request.json.get('ppid') user = User.query.get(session['user_id']) user.lemma_ppid = ppid db.session.commit() return jsonify({'success': True, 'linked': True})

Migrating from Password Auth

Add Lemma.id first, then gradually phase out passwords.

Step 1: Add alongside passwords (zero risk)
# Add lemma_ppid to users table ALTER TABLE users ADD COLUMN lemma_ppid TEXT UNIQUE; # Add Lemma endpoint (existing password auth unchanged) # Add SDK script tag to login page # Add "Sign in with Lemma.id" button
Step 2: Prompt existing users to link
// After user signs in with password, offer to add Lemma.id if (!user.lemma_ppid) { showBanner('Add Lemma.id for faster sign-in next time'); } // When user clicks, link their PPID to their existing account async function linkLemma() { const result = await wallet.getAuthenticatedPPID(); if (result.authenticated) { await fetch('/api/auth/link-lemma', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ ppid: result.ppid }) }); } }
Step 3: Deprecate passwords (optional)
# Stop accepting new password registrations # Existing password users can still sign in # Over time, all users migrate naturally # What you can remove after full migration: # - bcrypt/argon2 dependency # - Password reset flow (emails, tokens, rate limiting) # - MFA infrastructure (TOTP, SMS, backup codes) # - Account lockout logic # - Password validation rules

Instant Lock Detection

When a user locks their wallet on any device, your site detects it instantly via SSE.

JavaScript
// The SDK automatically connects to SSE for lock/unlock events. // Listen for the wallet-locked event to sign out on your site: window.addEventListener('lemma-wallet-locked', async () => { await fetch('/api/auth/logout', { method: 'POST' }); window.location.reload(); }); // That's it. No polling. No heartbeat. SSE pushes the event in <100ms.

Revoking a User

Site admins can revoke user access. The revocation propagates to all devices in under 1 second via SSE.

cURL (Admin API)
# Revoke a specific user from your site curl -X POST https://lemma.id/api/wallet/revoke-user \ -H "Content-Type: application/json" \ -d '{ "ppid": "did:lemma:ppid_abc123...", "site_id": "yoursite.com", "reason": "terms_violation" }' # The user's credential is immediately invalid. # Their browser's SDK detects the revocation via SSE within 1 second. # Re-issuance: issue a new credential (different credential_id, same PPID).
