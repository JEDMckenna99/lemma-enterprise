1) Verify proofs — free

Call verifyForBackend (or drop in <lemma-signin> to mint a presentation) and verify locally on your backend. No account or API key needed. Keep your existing login; gate trials, claims, and payouts.

  • Set siteId to your canonical hostname (for example app.example.com).
  • Add proof-verifier.js and fail closed when verification fails.
  • Enforce on verified ppid + assurance — no KYC fields on your servers.
Quickstart SDK integration

2) Step up to isHuman

When a ban has to stick, require ishuman on that action — same PPID, stronger assurance. The SDK handles IDV in a Lemma-hosted popup; no webhooks.

  • First visit may open a popup (lemma.id unlock + Didit IDV).
  • Later checks validate locally, no per-page network call.
  • Optional: stamp actions and re-verify on your backend with verifyStamp().
Integration flow API reference

3) Enforce bans — API key

API keys exist only for enforcement: server-side site-block on registered sites. Neither local verify nor isHuman step-up requires one.

  • POST /api/ishuman/site-block, immediate site-scoped PPID ban.
  • POST /api/ishuman/site-unblock, remove a site block.
  • Issue keys in the API key manager.
