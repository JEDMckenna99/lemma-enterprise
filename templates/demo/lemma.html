Why integrators use lemma.id

Without lemma.id

  • Each site runs its own verification — users repeat signup friction everywhere
  • You store emails, phones, or device signals to recognize the same person
  • Network-wide blocklists — one ban follows users across unrelated sites

With lemma.id

  • One passkey wallet — the isHuman proof lives in a single lemma.id only the user controls
  • Sites request site-private stamps from that wallet; your backend verifies them offline
  • Revoke a site-private ID on your site only — other sites are unaffected

    Developer details

    Assurance tiers

    passkey

    • Default for most site flows.
    • Fast unlock; no IDV required.
    • Site verifies a signed site-private stamp offline.

    ishuman

    • Stronger proof a site can require on doubt or high-risk actions.
    • Same PPID — assurance tier changes, not the account.
    • Completed via IDV when the site policy demands it.

    Integration snippet

    Start with passkey assurance; raise to isHuman only when your site policy requires it.

    <script src="https://lemma.id/sdk/ishuman-verifier.js"></script> const { ok, ppid, assurance, presentation } = await new IsHumanVerifier({ siteId: 'tickets-demo.lemma.id', autoProvision: true, requiredAssurance: 'passkey', }).verifyForBackend({ requiredAssurance: 'passkey' }); // Site step-up: requiredAssurance: 'ishuman' — same ppid, assurance: ishuman
