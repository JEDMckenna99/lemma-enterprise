1. Mathematical Foundations

Definition of "Lemma" in Mathematics

In mathematical logic, a lemma is a proven proposition used as a stepping stone toward a larger result or theorem. It's a foundational result that simplifies or enables the proof of more complex statements.

By analogy, Lemma (the company) views verified human identity as a fundamental building block – a "lemma" – in the construction of a more trustworthy and sybil-resistant internet. Just as a lemma in math provides a base truth to build upon, Lemma's verified unique personhood credential provides a base level of trust on which applications can rely to prevent fraud and abuse.

2. Proof-of-Personhood as a Primitive

Verifying uniqueness and humanness serves as a primitive in security and network design, akin to a low-level function that higher-level protocols can call. Establishing a one-to-one mapping between real humans and credential holders addresses the Sybil attack problem by mathematically constraining identity: ideally one human = one credential.

We can define a function \(f: \text{humans} \to \text{credentials}\) that is injective (one-to-one), then:

\(\forall h_1, h_2 \in \text{humans}: h_1 \neq h_2 \Rightarrow f(h_1) \neq f(h_2)\)

This means that no two distinct humans share the same credential and no single human has more than one valid credential.

Verifying humanness (that a user is a real human) and uniqueness (that they haven't obtained multiple credentials) becomes a basis for fairness in voting (one person–one vote), equitable airdrops in Web3, prevention of duplicate accounts in social platforms, and more. By treating proof-of-personhood as a first-class primitive, Lemma enables higher-level systems to assume "each credential = unique human," dramatically reducing the complexity of defending against bots and duplicate identities.

3. Probabilistic Models for Assurance

Some aspects of Lemma's approach involve probabilistic reasoning to balance efficiency with assurance:

Uniqueness Assurance

In practice, absolute one-to-one enforcement may be probabilistic. We rely on strong biometric matching and ID validation (via Stripe Identity) to ensure each real person can only obtain one credential.

The chance of one person spoofing a second credential is extremely low (requiring falsified government ID plus defeating biometric checks). We can model the probability \(P(\text{duplicate credential})\) as negligibly small – for example, if Stripe's false acceptance rate for matching a face to a different ID is, say, \(10^{-6}\), then the confidence level that each credential is uniquely tied to one person is \(>99.9999\%\).

In other words, the system treats this as nearly certain, acknowledging only a minute probabilistic risk. This is a vast improvement over CAPTCHA or heuristic bot detectors, which have significantly higher false acceptance rates for bots.

Revocation via Bloom Filters

Lemma's revocation system uses a Bloom filter, a space-efficient probabilistic data structure, to encode revoked credential identifiers.

Bloom filters may yield false positives (reporting a credential as "possibly revoked" when it isn't) with a very low probability, \(\epsilon\). By tuning filter size and hash functions, we keep \(\epsilon\) extremely small (e.g., \(10^{-6}\) or less) so that the odds of a valid credential being falsely flagged are negligible.

For a Bloom filter with \(m\) bits, \(n\) inserted elements, and \(k\) hash functions, the false positive probability is approximately:

\(\epsilon \approx (1 - e^{-kn/m})^k\)

We can solve for the optimal number of hash functions \(k\) that minimizes \(\epsilon\):

\(k_{opt} = \frac{m}{n} \ln 2\)

This allows purely local revocation checks without contacting a server, at the cost of an infinitesimal chance of false alarm. The design accepts this probabilistic trade-off for greater decentralization and privacy, while procedures (like re-checking or re-issuance) can handle the rare false positive if it occurs.

Probabilistic Uniqueness Metrics

We can also use probabilistic models to estimate system-wide uniqueness integrity. For instance, if \(n\) individuals attempt to game the system by obtaining multiple credentials, and each attempt has probability \(q\) of being caught (or conversely \(1-q\) of slipping through), then the expected number of duplicate credentials is binomial with mean \(n(1-q)\).

With robust KYC and biometric matching, \(q\) is very close to 1, making \(n(1-q)\) near zero in expectation. This gives a quantitative assurance that large-scale sybil attacks are infeasible under our model.

4. Zero-Knowledge Proofs for Minimal Disclosure

Lemma employs zero-knowledge proofs (ZKPs) to enable selective disclosure of credential data. The core idea is that a user can prove a statement true without revealing the underlying secret.

A zero-knowledge proof system has three fundamental properties:

  1. Completeness: If the statement is true, an honest verifier will be convinced by an honest prover.
  2. Soundness: If the statement is false, no cheating prover can convince an honest verifier that it is true, except with some small probability.
  3. Zero-knowledge: If the statement is true, the verifier learns nothing other than the fact that the statement is true.

In Lemma's context, the credential might include various attributes (e.g., a unique user ID or hash, an issuance timestamp, perhaps age or nationality if those were verified). However, when a user needs to prove "I am a verified human" to a website, the site should not need to learn any other identifying information.

Using ZKPs, Lemma can furnish a proof that "This user possesses a valid credential with the claim \(\texttt{isHuman: true}\), issued by Lemma, and not revoked" without exposing any personal data or even a stable identifier.

For example, we can use a signature scheme like BBS+ or CL signatures that support selective disclosure: the credential is signed in such a way that the holder can generate a derived proof revealing only the \(\texttt{isHuman}\) attribute (and perhaps an expiration or issuer reference), while hiding attributes like the internal unique ID.

The verifier can cryptographically check the proof's validity (ensuring it was issued by Lemma and is unrevoked) but learns nothing else about the user. This application of zero-knowledge techniques preserves privacy and prevents cross-site correlation of user identities – each relying party only learns the user is a valid unique human, nothing more.

5. Pricing Model Mathematics

Network Effect Pricing Function

Lemma's business model includes a subscription-like component with a monthly fee per active user that decays exponentially as the number of participating sites increases. This creates a network effect that incentivizes broad adoption.

We define the per-user price as a function of the total number of integrated sites, \(N\):

\[p(N) = p_0 e^{-\alpha N}\]

Where:

  • \(p_0\) is the base monthly per-user fee when the network is very small (effectively when \(N \to 0\) or 1)
  • \(\alpha\) is a constant that controls the rate of decay of price with each additional site

We choose \(\alpha\) such that after a certain number of sites \(M\), the price drops by half (50%). Specifically, if we want the price to halve after \(M\) sites join, we set:

\[\alpha = \frac{\ln(2)}{M}\]

For example, with \(p_0 = \$0.50\) per user/month at the start (1 site) and \(M = 10\) sites to halve the price:

  • At \(N = 5\) sites, price \(p(5) \approx \$0.35\) per user/month
  • At \(N = 10\) sites, \(p(10) \approx \$0.25\) per user/month (half of \(\$0.50\))
  • At \(N = 20\) sites, \(p(20) \approx \$0.125\) per user/month

In the limit of very large \(N\), \(p(N)\) approaches 0 (though realistically it might bottom out at some minimal operational cost floor).

Network-Driven Discounts and Retroactive Pricing

This pricing model creates a federation incentive: early adopters pay more initially, but as they help grow the network (directly or indirectly), the price per user for everyone (including them) goes down.

Ed25519 Signatures

The Ed25519 signature scheme uses the Edwards curve:

\[-x^2 + y^2 = 1 - \frac{121665}{121666} x^2 y^2\]

over the finite field \(\mathbb{F}_p\) where \(p = 2^{255} - 19\).

For a message \(M\), private key \(k\), and public key \(A = [k]B\) (where \(B\) is the base point):

  1. Compute \(r = H(H(k) || M)\) (mod \(l\))
  2. Compute \(R = [r]B\)
  3. Compute \(h = H(R || A || M)\) (mod \(l\))
  4. Compute \(s = (r + hk)\) (mod \(l\))
  5. The signature is \((R, s)\)

Mathematical Proofs

Proof: Optimal Bloom Filter Hash Count

To find the optimal number of hash functions \(k\) that minimizes the false positive probability \(\epsilon\) for a Bloom filter with \(m\) bits and \(n\) inserted elements:

The probability that a specific bit is still 0 after inserting \(n\) elements with \(k\) hash functions is:

\[p = \left(1 - \frac{1}{m}\right)^{kn} \approx e^{-kn/m}\]

The probability of a false positive is:

\[\epsilon = (1 - p)^k = (1 - e^{-kn/m})^k\]

Taking the derivative with respect to \(k\) and setting it to zero:

\[\frac{d\epsilon}{dk} = 0\]

Solving this equation gives:

\[k_{opt} = \frac{m}{n} \ln 2\]
